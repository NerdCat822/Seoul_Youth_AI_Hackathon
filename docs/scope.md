# 구현 범위

## 자료 기준

- 사용자 제공 `TalkFile_가늠_목업.html.html`: 화면 흐름, 색상, 카드, 하단 메뉴의 기준.
- 사용자 제공 `TalkFile_가늠 · 해커톤 기획서.pdf.pdf`: 서비스 목적과 단계별 기능의 기준.
- 두 자료의 화면 표현이 다르면 HTML 최종 스타일을 우선한다.
- 첨부 자료의 전체 기능을 이번 기초 구성의 완료 조건으로 취급하지 않는다. 사용자 요청은 React / Spring 기반 분리 구조이며 DB는 후속 작업이다.

## 이번 기초 구성

- React 화면 및 브라우저 탐색, API 클라이언트.
- 홈, 시도 등록·조회, 달력, 내 기록, 동네 가상 사례.
- 구조화된 입력 폼과 필수값·날짜 범위 검증.
- Spring REST API, DTO, Service, Repository 분리.
- 서버 메모리 임시 저장 및 데이터 보관 안내.
- API 오류·로딩·재시도 처리.
- 가상 결과 예시: 세트 주문 42→58, 전체 주문 100→160, 비중 42%→36.25%.

## 후속 구현

- DB 및 사용자/가게별 데이터 분리, 인증.
- 자연어 입력을 구조화하는 AI, 음성 입력 및 읽어주기.
- 표준 엑셀의 실제 파싱과 판매 행 검증, 날짜별 집계 및 결과 저장.
- 사진 OCR, POS 연결, 알림.
- 실제 동네 데이터의 익명 집계 및 공개 기준.
- 기록 수정/삭제, 실제 분석 완료 처리.

AI 호출·음성 입력·판매자료 업로드를 현재 기능처럼 표시하지 않는다. 분석 예시는 저장한 시도의 실제 결과가 아니다.

## 향후 분석에서 지킬 원칙

- 숫자는 코드로 계산하고 AI는 입력 해석과 설명을 담당한다.
- 같은 요일 구성이 되도록 비교 기간을 맞춘다.
- 전체 주문 수와 해당 메뉴 주문 수를 함께 보고 비중을 계산한다.
- 자료 누락과 겹치는 시도를 확인하고 결과의 한계를 표시한다.
- 시도 전후의 변화만으로 원인과 효과를 단정하지 않는다.
