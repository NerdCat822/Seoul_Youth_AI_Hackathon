# 실수노트

사용자 제공 원본의 원칙을 프로젝트에서 계속 관리한다.

## 테스트했다고 말하기 전에 실제 실행하기
- 이슈: 확인했다고 했지만 소스가 실제로 실행되지 않았음.
- 규칙: 완료 보고에는 실행한 검증 결과를 포함한다. 실행하지 못한 항목은 미검증으로 표시한다.

## 기존 파일 마음대로 덮어쓰지 않기
- 이슈: 기존 파일을 백업 없이 새 파일로 덮어씀.
- 규칙: 기존 파일 수정 전 변경 내용을 먼저 설명하고, 필요한 부분만 수정한다. 사용자 제공 원본은 보존한다.

## 작업 중 새 교훈
- 2026-11-13: 첨부 HTML에 base64 글꼴이 포함되어 있다. 분석 시 base64 줄을 제외해 코드와 요구사항이 출력 제한으로 누락되지 않도록 한다.
- 2026-11-13: 공통 예외 처리기가 Spring의 405/415까지 500으로 바꾸지 않도록 원래 HTTP 상태와 필요한 헤더를 보존한다.
- 2026-11-13: enum 문자열 계약은 Jackson 기본값만 믿지 않는다. 숫자 ordinal 입력 거절 설정과 경계 테스트를 함께 둔다.
- 2026-11-13: hash 화면 전환 직후 브라우저 테스트에서 이전 heading을 읽지 않도록 목표 heading/URL까지 기다린다.
- 2026-11-13: Windows 격리 실행 환경의 localhost가 외부 브라우저와 분리될 수 있다. 서버 실행 로그뿐 아니라 실제 브라우저 접속으로 연동을 확인한다.
- 2026-11-13: 로컬에 설치된 도구는 임시 선택의 편의일 뿐 기술적 필수 조건이 아니다. 사용자가 Gradle 선호를 밝혔으므로 빌드 설정·Wrapper·실행 문서를 함께 Gradle로 통일한다.
- 2026-11-13: Wrapper 생성·갱신은 빌드 검증과 구분한다. 갱신된 Wrapper 자체로 별도 `clean build`를 실행해 종료 코드와 테스트 결과까지 확인한다.
- 2026-11-13: 실행 안내에는 명령별 작업 폴더와 터미널을 명시한다. 계속 실행되는 서버에서 빌드·preview로 전환할 때는 기존 프로세스의 종료 순서도 함께 적는다.
